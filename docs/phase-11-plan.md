# Phase 11 Plan — Media Inspector / Extractor (`media.inspect`)

> Baseline: Phase 10 (`d4eeebc`) · Contract **v1.5.0 → v1.6.0 (additive)** · Builds directly on the
> checksum-proven toolkit paths pushed by main (`toolkit.setPaths`).

## Goal

Given a media page URL, produce a validated `MediaManifest` (video formats / audio formats /
subtitle tracks) by running the **bundled yt-dlp** from the Rust core. This is the inspection
half of the media pipeline; Phase 12 builds the download & merge flow on top of the selected
formats.

## Key decisions

1. **Inspection runs in the Rust core.** The core already owns the two pieces of state that
   matter: the `ToolkitMap` (only checksum-proven executables) and the runtime `ProxyMap`
   (profile → endpoint). Spawning yt-dlp anywhere else would duplicate fail-closed tool
   resolution and leak proxy secrets across an extra boundary. Architecture invariant holds:
   `Renderer ↔ main ↔ core ↔ yt-dlp`.
2. **Fail-closed tool resolution.** No yt-dlp in the map → `media_tool_missing` (UI points the
   user at Settings → Media toolkit). The core never probes `PATH`, never fetches tools.
3. **Process hygiene (security).**
   - URL must be `http(s)` — anything else → `url_invalid` before a process is spawned.
   - argv-array spawn (`tokio::process::Command`), **no shell**, so URLs cannot inject args.
     yt-dlp's argv contract keeps this safe; leading `-` in a URL is rejected anyway.
   - `--ignore-config --no-progress --no-warnings --no-playlist --dump-single-json` —
     deterministic, machine-readable, no user config interference.
   - Hard timeout (90 s) with child kill → existing `timeout` code; stdout capped at 64 MiB
     (runaway output cut → `media_invalid_response`); stderr tail (≤16 KiB) captured for
     error classification.
   - Concurrency capped by a `Semaphore(3)` — excess inspects wait instead of spawning
     process storms.
4. **Normalization (core-side projection yt-dlp JSON → `MediaManifest`).**
   - `videos`: formats with a real video codec (`vcodec` present, ≠ `none`, ext ≠ `mhtml`,
     no `storyboard` note). `acodec` carried through for progressive files (null when audio
     is absent). Sorted height ↓, fps ↓, bitrate ↓; deduped by formatId.
   - `audios`: audio-only formats (`acodec` present ≠ `none`, `vcodec` = `none`/absent),
     sorted by bitrate ↓.
   - `subtitles`: manual tracks first (`subtitles`, isAutoGenerated=false), then automatic
     captions (`automatic_captions`, isAutoGenerated=true) limited to `vtt` ext (and the
     `-orig` source language when yt-dlp marks it) so a YouTube page yields dozens of rows,
     not hundreds.
   - Playlist responses (`_type: playlist`) → `media_playlist_unsupported` (single-item
     inspect only; batch playlists are a later-phase decision).
5. **Proxy routing.** Optional `proxyProfileId` → resolved in the runtime map (missing →
   `proxy_profile_not_found`, fail-closed) → passed to yt-dlp as `--proxy <endpoint>` with
   basic auth in the URL, exactly like the download engine builds its proxied clients.
6. **Contracts v1.6.0 (additive only).**
   - New core method `media.inspect` `{ url, proxyProfileId? } → { manifest }`.
   - `MediaManifest.isLive: boolean` (live streams surface honestly; Phase 12 decides merge
     policy). `VideoFormat.acodec: string | null` (progressive formats carry audio).
   - New append-only error codes: `media_tool_missing`, `media_extract_failed`,
     `media_playlist_unsupported`, `media_invalid_response`.
   - Fixture `mediaManifest` refreshed (isLive + acodec) and consumed by **both** vitest and
     `cargo test` (wire-format parity, same as every prior phase).

## Test plan

- **contracts (vitest)**: v1.6 schema additions, https-only source URLs, error-code registry
  growth, media.inspect in METHODS with `server: "core"`, refreshed fixture validity.
- **dc-protocol (cargo)**: media wire round-trip + `mediaManifest` fixture byte-parity.
- **download-core (cargo)**: normalization table (progressive/DASH/storyboard/audio-only/
  captions/auto-captions/playlist/malformed), sort + dedupe rules, URL scheme rejection,
  leading-dash rejection, stdout cap, error classification; **integration** via a fake
  `yt-dlp` executable (shell script, cfg(unix)) pushed through `toolkit.setPaths`: happy
  path, nonzero exit → stderr excerpt, timeout kill, proxy arg passthrough, missing tool.
- **main (vitest)**: media domain registration forwards to the supervisor (mocked), boundary
  schemas validate.
- **renderer (vitest)**: media store transitions (idle → inspecting → ready / error).
- **Gate**: cargo fmt + clippy `-D warnings` + tests green; vitest green; typecheck ×4;
  vite build.

## Out of scope (later phases)

Format selection download + mux (Phase 12), playlist batch inspection, live-stream
recording, browser-tab "inspect this page" integration.
