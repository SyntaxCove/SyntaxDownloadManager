## Discoveries that shaped the implementation

- **electron-builder 26 removed the root `zip` config key** (schema-validated). The
  portable zip's artifact name is the root `artifactName`; the NSIS target overrides its
  own via `nsis.artifactName`. Both are asserted by the drift-guard test so a future
  electron-builder bump cannot silently rename release artifacts.
- **NSIS on Linux runs makensis through wine.** This sandbox's kernel policy kills wine
  at `wineboot` (SIGSYS). The NSIS target is therefore validated by schema, drift-guard,
  and a launched (toolchain-downloaded) build that stopped only at the wine execution
  layer; the installer itself is produced by `scripts/build-windows.ps1` on Windows,
  where wine is not involved. The zip target does not need wine and completed fully.
- **`react`/`react-dom`/`zustand` moved to devDependencies** — the renderer is bundled by
  Vite; the asar now carries true main-process runtime dependencies only
  (`packaging-note` in `apps/desktop/package.json` records the rationale).

## Honest limitations

- **Unsigned build** — no Authenticode certificate yet. Integrity today = https
  transport + feed-embedded sha512 + blockmap (Phase 18 design); authenticity is the
  code-signing upgrade path at release engineering (per the Phase 18 plan's decision
  record). SmartScreen will warn on first run until then.
- **The attached v0.6.0 portable zip is cross-built** in the Linux sandbox: the
  JavaScript/Electron side is byte-for-byte the standard electron-builder output; the
  Rust core inside was cross-compiled with mingw from the exact source that passes the
  268-test suite natively. GUI execution on real hardware remains the user-side step
  (established environment split); the user-side script rebuilds both from source.
- `app-update.yml` inside the portable zip points at this GitHub repository's releases;
  publishing `latest.yml` alongside release assets is part of release engineering (the
  app-side channel already treats a missing feed as classified `unavailable`, never a
  fallback).
